烘焙数据如何参与画面

  • 照明：按天光、三个太阳方向、室内灯分别计算直接与间接漫反射。开关灯和三个增益控件只改变对应线性分量，灯关后不保留灯光；固定状态下取代旧漫反射，避免重复加亮。
  • 家具：从实际组装位置烘焙，不再只靠每个房间均匀的近似填充。桌面和手机LOD各自采样，按位置/法线及顶点索引匹配；几何未改动。
  • AO：全场景计算墙角、柜背和家具接触遮蔽。建筑漫反射已包含路径遮挡，AO主要轻量约束环境高光；家具AO保守作用于间接填充。使用静态数据时关闭屏幕AO合成，减少叠黑，手机继续不使用深度AO。
  • 反射：毛坯与A各10个房间探针。离线全景按当前自然光与灯光线性合成，再生成PMREM供木材、石材、五金和玻璃使用；保持盒投影和各材质自身反射强度。
  • 数据预算：建筑仅新增一张当前状态的1024²纹理；家具光照写入顶点属性；反射按房间使用。解码Float32图像缓存限制约48MiB，过期状态释放，单HTML仍自包含。

固定状态的边界

参考门状态为入户门关闭、6扇房间门平开并打开，采用各方案原定材质。改门、换墙顶地材质或隐藏天花板后恢复原有照明与动态反射，避免使用不匹配的静态阴影；个人设置照常保存。新状态首次解码和生成反射前短暂使用原照明，后续切换可复用解码缓存。

反射探针使用实际几何、基础底色与粗糙度，未复制室外城市的全部细节及全部材质纹理；固定机位探针不能精确反映任意视点的镜面。烘焙灯具亮度为网页视觉标定，不能作为实际照度设计。单HTML约24MB，比原版增大；需要真机验证实际网络加载和长时间性能。

可复现流程与依据

仓库 assets/static-bake/ 保留导出场景、可编辑Blender场景、PNG数据与内嵌包。先运行 scripts/export_static_bake_scene.cjs，再执行 scripts/bake_static_cycles.py，最后构建HTML；烘焙脚本、墙线、家具模型与导出输入哈希不匹配时构建拒绝过期资源。

烘焙通道与直接/间接漫反射分离参考 Blender官方 Cycles Baking 文档，输出按线性数据处理。运行时沿用项目内嵌Three r128的PMREM及WebGL1材质。
