## T02 其他户型适配

**目标**：支持当前 89-A 之外的户型，并能按户型正确展示、配置和保存。

**现有基础**：当前实现围绕 89-A；墙线、门洞、门配置和原图实黑标记以 `src/plan-layout.json` 为共同来源。新增户型的清单、图纸和尺寸资料待整理。

- [ ] T02.1 整理户型清单及来源，选择首个新增户型，标记已知尺寸、朝向和待确认部分。
- [ ] T02.2 梳理房间、墙线、门窗、楼层、朝向及材质的数据边界，设计按户型组织的配置结构。
- [ ] T02.3 接入首个新增户型，生成对应平面图、三维模型与烘焙数据，并提供户型切换。
- [ ] T02.4 验证各户型的门、碰撞、屋顶覆盖及设置隔离，回归当前 89-A。

**验收标准**：至少完整接入一个新增户型；图纸与网页来自同一份布局数据；墙体保持正交，门窗、朝向和房间对应正确；各户型独立保存设置并兼容既有 89-A 设置。切换后三种浏览模式、烘焙纹理和移动操作正常，估算部分有明确说明。

## T03 小区效果展示

**目标**：从单户展示扩展到小区尺度，展示楼栋布局、公共空间、景观及户型所在位置。

**现有基础**：已有透明楼栋和程序化住宅环境，小区资料存放在 [references/phmt/](../references/phmt/README.md)。现有楼栋与周边环境包含示意内容。

- [ ] T03.1 收集并核对总平面、楼栋位置、层数、立面和景观资料，逐项记录来源与不确定性。
- [ ] T03.2 明确展示范围和精度，形成小区场景方案及模型、贴图、性能预算。
- [ ] T03.3 实现小区总览、楼栋识别与户型位置展示，连通小区和户内浏览。
- [ ] T03.4 验证远近景、昼夜及移动端表现，整理整体和局部展示图。

**验收标准**：可查看小区整体、识别楼栋并定位当前户型；确认资料与示意内容清晰区分，不把未知层数或其他户型描述为测绘结果。场景切换和移动端操作正常，资源与性能满足确定后的预算。

## T04 家具可配置

**目标**：从毛坯 / A 方案切换扩展到家具级配置，使用户能够调整自己的布置方案。

**现有基础**：`src/decor-preset-a.js` 提供独立家具层，支持毛坯 / A 切换及分方案材质保存；现有家具布局主要由代码固定。

- [ ] T04.1 确定首批家具清单和操作范围，包括显隐、款式、颜色 / 材质、位置、旋转，以及是否允许调整尺寸。
- [ ] T04.2 建立家具编号、配置结构和边界规则，设计桌面及手机编辑操作。
- [ ] T04.3 实现首批家具配置、方案恢复及保存 / 导入 / 导出，处理已有设置兼容。
- [ ] T04.4 验证家具与墙体、门扫掠、通道的关系，以及配置后的漫游和刷新恢复。

**验收标准**：首批确认的家具可按约定属性编辑，刷新和 JSON 导入导出后配置一致；提供恢复方案默认值的操作。家具调整不改变建筑烘焙快照；运行 `houseBakeSource()` 一致性、`decorDoorClearance()` 与可移动位置检查。卧室床头 / 柜背贴墙、床其余三侧通行及房门扫掠按既有要求验证。

## T05 墙可拆可增

**目标**：支持在方案中删除或新增允许编辑的墙体，并同步更新空间显示、门洞、碰撞与光照。

**现有基础**：当前墙体为固定布局，图纸与网页共享 `src/plan-layout.json`；建筑照明使用离线烘焙。可编辑墙体范围和编辑后的光照更新方式需要先确定。

- [ ] T05.1 确定可编辑墙体和保护规则，沿用原图实黑区域标记，明确结构信息待核实的范围。
- [ ] T05.2 评估墙体编辑后的门洞、房间划分、材质、碰撞和光照更新，选择可落地的实施方式。
- [ ] T05.3 实现正交墙体新增 / 删除、尺寸输入或吸附，以及撤销 / 重做和恢复原始方案。
- [ ] T05.4 同步图纸与三维场景，实现方案保存 / 导入 / 导出，完成几何、门、通行与光照验证。

**验收标准**：在约定范围内可增删墙，墙体始终横平竖直；图纸、模型、门洞、材质与碰撞保持一致，原方案可恢复，保存后可重现。不得自动把厚墙都认定为承重墙；编辑范围及保护规则在实施前明确。涉及建筑几何或门洞的变更，必须导出新烘焙源并完成重绘、灯光 / 太阳 / 天光重烘焙和构建；浏览器编辑方案需明确生效及光照更新流程，避免沿用失效贴图。

## 依赖与实施准备

- T01 可先确定视觉基准，随后用于新增户型、小区场景和家具编辑的展示验收。
- T02、T03 先整理对应图纸与资料，再确定模型范围；新增户型所需家具配置需与 T04 的户型隔离方案衔接。
- T04 可从当前 A 方案的少量家具开始，逐步扩充；家具编辑保持建筑墙线和门洞独立。
- T05 先解决几何与光照更新方式，再开展交互实现；其布局数据结构应与 T02 衔接。

各项实施均保留单 HTML 自包含、WebGL1、手机 / 微信适配和既有个人设置。按改动范围执行 [开发验证](DEVELOPMENT.md)；main 验证、提交、推送并检查测试部署，正式发布按独立流程推进。
