# 手机和微信显示验证

V14.2检测链接：[在当前浏览器运行显示检测](https://aimspike.github.io/HangZhouPHMT/?release=14.2&verify=mobile)。普通看房链接为[正式展示页](https://aimspike.github.io/HangZhouPHMT/?release=14.2)。检测仍使用同一份自包含HTML，不会额外请求测试脚本或第三方诊断服务。

## 用实际手机完成验证

1. 在发生问题的手机微信中打开检测链接，确认下方面板标题为“V14.2 · 本机显示检测”。若标题仍旧，关闭原网页后重新打开完整检测链接。
2. 检查毛坯正午、毛坯夜晚、家装A正午、家装A夜晚四项。可收起检测面板，拖动转向，检查天花板、窗边墙面及地板。每项按实际结果点击“此项无条纹”或“此项仍有条纹”，再切下一项。
3. 点击“复制检测报告”，粘贴回维护对话，并附手机型号。无法自动复制时，报告文本会展开，可长按选取复制；也可下载JSON。
4. 用微信右上角菜单转到系统浏览器，在同一台手机的Safari或Chrome再次打开完整检测链接，完成同样四项并返回报告。两个浏览器的报告分别保留，不能用其中一个代替另一个。
5. 退出检测链接后确认个人材质、画质、门和时段设置仍恢复。检测会读取现有本地设置，但临时操作不写回、不连接云账号，也不弹赞赏提示。

报告包含版本、浏览器UA、WebGL浮点精度、画布尺寸、贴图数量、阴影策略、帧推进和四项人工目视结果；不包含账号、令牌、邮箱或设置内容，不自动发送到任何服务。测试未作人工判断时保持 `awaiting-visual-check`，自动检查通过不能变成人工视觉通过。返回报告是使用者主动操作。

## 验证范围和工具限制

`validation/verify-mobile-compatibility.cjs`覆盖Chromium和Windows WebKit、iPhone Safari/微信UA、Android Chrome/微信UA、触摸与横竖屏、已保存精细档、四场景检测入口和检测前后localStorage完全一致；其中WebKit仍是Windows运行，不是iOS真机或微信应用。测试脚本不会点击“无条纹”来伪造人工结果。

上次仅将深度缓冲改为16位，不足以模拟手机的深度纹理采样精度。V14.1在深度读取量化到10位的小数时再次出现重复条纹，证明前次修复没有覆盖此情况；这是一种可重现的故障模型，尚不能单凭该模型断言用户具体GPU的内部精度。

V14.2为深度纹理显式声明highp采样；手机、触屏、微信使用烘焙阴影和房间反射，不附加屏幕AO深度纹理，也不向FXAA注入深度合成shader。该策略作用于所有画质档，不修改用户保存的画质值。桌面具备highp和depth扩展时继续AO，否则回退。A方案已有家具地面接触贴片保留。

本地检查没有发现可用的USB调试手机，也没有配置云真机服务。尝试访问电脑微信窗口时应用授权超时，未完成电脑微信UI验证；即使完成也不能代替手机微信。只有收到从实际手机微信和系统浏览器返回的报告及目视结论，才能补记真机结果。

需要直接远程调试时，可由用户连接已授权的Android调试设备及相应浏览器；iPhone可由用户在具备相应调试环境的设备上检查。不要绕过微信、系统或浏览器的调试权限，不把云测试账号或设备标识写入仓库。
